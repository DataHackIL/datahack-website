# DataHack site migration preview

This Cloudflare Pages app is isolated from the legacy Jekyll site in the repository root. It covers the public Wix sitemap: home and team. Static content and locally bundled public Wix assets build offline.

From this directory, run `python3 build.py` and `node --test *.test.mjs` (Node 22+). To serve static files with clean URLs and test the Pages Functions, run `wrangler pages dev ./dist`.

`design/` contains the rendered public Wix layouts for both pages, responsive styles, local images and fonts. It does not load the Wix web application, analytics or form service. The optional refresh command `python3 capture_design.py` requires Playwright and Google Chrome, and only works while the original site is still available. Normal builds and serving do not need Wix. Review the markup and assets before redeploying. `assets/mirror.js` handles site navigation. Newsletter signup goes to the existing standalone signup page; submitting the contact form does not subscribe anyone.

The Pages middleware makes only `datahack.org.il` indexable; all other hosts receive `noindex, nofollow`. Home and team canonical URLs point to the apex. GET and HEAD requests to `www.datahack.org.il` redirect to the apex when that hostname reaches this project; POST requests are never redirected. Deploy using the DataHack account credentials. Do not commit credentials or change domain associations as part of a routine deploy.

The form deliberately returns 503 until the Workspace delivery adapter is configured. Deploy `mail-relay/` as a Google Apps Script web app under the designated DataHack technical account, executing as the deployer. Its only OAuth scope is sending mail; it cannot read Gmail. Set a random shared `CONTACT_TOKEN` in Script Properties and as a Cloudflare Pages secret. Set the deployment's `https://script.google.com/macros/s/.../exec` URL as the Pages `CONTACT_WEBHOOK` secret. Do not publish the endpoint or value in Git. The relay only sends to `contact@datahack.org.il`, reserves at most 35 sends per UTC day, and returns an explicit acknowledgement after MailApp accepts the send. Cloudflare follows only Google's Content Service redirect, without replaying the submission. Add production abuse protection and verify a tagged message arrives in the destination inbox before cutover. The unit tests mock the relay; they do not prove inbox delivery.

The preview relay is named **DataHack Website Contact Relay** in the DataHack technical Workspace account. Save both values as encrypted secrets in the Pages production environment for this preview project, then deploy again: already-published deployments do not acquire new secrets. For diagnosis, a 503 means configuration is missing; a 502 means delivery could not be confirmed and is not proof that mail did not arrive. Compare one uniquely tagged test with the inbox, Apps Script Executions and the Pages function logs before retrying. Function warnings record only the failed stage, not form contents or secret values.

The contact form requires the **DataHack Website Contact** Cloudflare Turnstile widget and a `TURNSTILE_SECRET` Pages secret. The public site key in the build is not a secret. Only the stable review hostname is configured today. Add approved production web hostnames to the widget before any cutover. The Pages Function requires a successful Siteverify response with the matching hostname and `contact` action before forwarding a message to Workspace. No-interaction tests may use Cloudflare's documented test keys locally; never use those on a live deployment.

Before cutover: get separate approval after the stakeholder reviews the Pages URL, confirm content and design, audit Wix functionality outside the public sitemap, and verify the custom domain and form again after migration. Preserve existing MX and other unrelated records and capture the current web records for rollback. Enable indexing and canonical URLs only for the approved production deployment. Do not remove Wix or request cancellation before production smoke tests pass.
